# Сборник сложных задач по Python

## 1. Склад: самый дефицитный день

На складе каждый день фиксируют изменение количества товара: положительное число означает поставку, отрицательное — расход, ноль — отсутствие движения.

Нужно определить, сколько дней был зафиксирован расход товара, а также найти день с самым большим расходом. Самым большим расходом считается наиболее отрицательное значение. Если одинаковый максимальный расход встречался несколько раз, нужно вывести номер последнего такого дня.

### Формат ввода

В первой строке дано целое число `n` — количество дней.

Далее следуют `n` строк, в каждой записано одно целое число — изменение количества товара за соответствующий день.

Ограничения:

`0 ≤ n ≤ 1000`

`-100000 ≤ изменение ≤ 100000`

### Формат вывода

Если `n = 0`, вывести одну строку:

```text
Нет данных
```

Иначе вывести две строки:

```text
Дней с расходом: <количество>
Максимальный расход: день <номер дня>, изменение <значение>
```

Если отрицательных значений не было, во второй строке вывести:

```text
Максимального расхода не было
```

## 2. Курьер: серия успешных доставок

Курьер в течение дня получает заказы. Для каждого заказа записывается время доставки в минутах. Значение `0` означает отменённый заказ и в статистику времени не входит.

Доставка считается быстрой, если заняла не более 30 минут.

Нужно определить количество выполненных заказов, среднее время выполненной доставки и длину самой длинной серии быстрых доставок подряд. Отменённый заказ прерывает серию.

### Формат ввода

В первой строке дано целое число `n` — количество заказов.

Далее следуют `n` строк, в каждой записано целое число — время доставки в минутах или `0`, если заказ был отменён.

Ограничения:

`0 ≤ n ≤ 1000`

`0 ≤ время ≤ 300`

### Формат вывода

Если выполненных заказов не было, вывести:

```text
Нет выполненных заказов
```

Иначе вывести три строки:

```text
Выполнено заказов: <количество>
Среднее время: <значение>
Максимальная серия быстрых доставок: <длина>
```

Среднее время округлить до двух знаков после запятой функцией `round`.

## 3. Копилка: до первой цели

Студент копит деньги на ноутбук. Целевая сумма задаётся в начале. После этого по одному вводятся пополнения счёта.

Положительное число — пополнение. Ноль означает пустое уведомление банка и не считается операцией. Отрицательное число означает ошибочный ввод: такая строка не должна учитываться ни в сумме, ни в количестве операций.

Ввод заканчивается словом `stop` либо автоматически сразу после того, как накопленная сумма стала не меньше цели.

Нужно определить количество засчитанных пополнений, итоговую сумму и способ завершения накопления.

### Формат ввода

В первой строке записано целое положительное число — цель накопления.

Далее вводятся строки, каждая из которых содержит либо целое число, либо слово:

```text
stop
```

Если цель не достигнута, ввод гарантированно завершится словом `stop`.

Ограничения:

`1 ≤ цель ≤ 1000000`

`-100000 ≤ сумма операции ≤ 100000`

не более 1000 строк операций.

### Формат вывода

Вывести три строки:

```text
Пополнений: <количество>
Накоплено: <сумма>
<статус>
```

Статус должен быть одним из двух:

```text
Цель достигнута
```

или

```text
Накопление остановлено
```

## 4. Экзамен: лучшая попытка

Студент несколько раз проходит тренировочный тест. Для каждой попытки записывается результат от 0 до 100.

Попытка считается успешной, если результат не меньше 60.

Нужно определить количество успешных попыток, номер лучшей попытки и её результат. Если максимальный результат встречался несколько раз, нужно вывести номер первой такой попытки.

Дополнительно нужно определить, улучшил ли студент результат хотя бы один раз по сравнению с непосредственно предыдущей попыткой.

### Формат ввода

В первой строке дано целое число `n` — количество попыток.

Далее следуют `n` строк, в каждой записано целое число от 0 до 100.

Ограничения:

`0 ≤ n ≤ 1000`

### Формат вывода

Если `n = 0`, вывести:

```text
Нет попыток
```

Иначе вывести три строки:

```text
Успешных попыток: <количество>
Лучшая попытка: <номер>, результат <балл>
Было улучшение: <Да или Нет>
```

## 5. Подписка: перерасход тарифа

Пользователь оплачивает мобильный тариф на месяц. В тариф включено определённое количество гигабайт интернета. Каждый день фиксируется расход трафика.

Нужно определить день, в который суммарный расход впервые превысил включённый лимит. Если лимит не был превышен, нужно вывести общий остаток трафика.

Дни с расходом `0` учитываются как обычные дни.

### Формат ввода

В первой строке записано целое число — объём включённого трафика в мегабайтах.

Во второй строке записано целое число `n` — количество дней.

Далее следуют `n` строк, в каждой записан расход трафика за день в мегабайтах.

Ограничения:

`0 ≤ лимит ≤ 1000000`

`0 ≤ n ≤ 1000`

`0 ≤ расход за день ≤ 100000`

### Формат вывода

Если лимит был превышен, вывести:

```text
Лимит превышен: день <номер дня>
Перерасход: <количество мегабайт>
```

Перерасход считается на конец того дня, когда лимит был впервые превышен.

Если лимит не был превышен, вывести:

```text
Лимит не превышен
Остаток: <количество мегабайт>
```

## 6. Пароль: ограниченное число попыток

Система хранит правильный пароль. Пользователю даётся ограниченное количество попыток входа.

Перед сравнением введённого пароля нужно убрать пробелы по краям строки. Регистр символов имеет значение.

Пустой ввод после удаления пробелов не считается попыткой.

Если пароль введён верно, программа должна немедленно завершить проверку. Если допустимое количество попыток исчерпано, доступ блокируется.

### Формат ввода

В первой строке записан правильный пароль.

Во второй строке записано целое число `k` — максимальное количество попыток.

Далее вводятся строки с вариантами пароля. Ввод гарантированно содержит достаточно непустых строк, чтобы либо пароль был угадан, либо попытки закончились.

Ограничения:

`1 ≤ k ≤ 20`

длина каждой строки не превышает 100 символов.

### Формат вывода

Если пароль был угадан, вывести две строки:

```text
Доступ разрешён
Использовано попыток: <количество>
```

Иначе вывести:

```text
Доступ заблокирован
Использовано попыток: <количество>
```

## 7. Анализ сообщения

Модератор получает одно текстовое сообщение и должен оценить его по нескольким признакам.

Сообщение считается подозрительным, если выполняется хотя бы одно условие:

- его длина после удаления пробелов по краям меньше 5 символов;
- в нём встречается слово `реклама` независимо от регистра;
- в нём больше трёх символов `!`;
- в нём нет ни одной буквы.

Нужно определить количество цифр, количество восклицательных знаков и итоговый статус сообщения.

### Формат ввода

Одна строка — текст сообщения.

Длина исходной строки не превышает 1000 символов.

### Формат вывода

Вывести три строки:

```text
Цифр: <количество>
Восклицательных знаков: <количество>
Статус: <Подозрительное или Обычное>
```

## 8. Температура: самая длинная жара

За `n` дней метеостанция записала дневную температуру.

Жарким считается день с температурой не ниже 30 градусов.

Нужно определить общее количество жарких дней, длину самой длинной непрерывной серии жарких дней и номер дня, когда эта серия закончилась.

Если несколько серий имеют одинаковую максимальную длину, нужно выбрать ту, которая закончилась позже.

### Формат ввода

В первой строке дано целое число `n` — количество дней.

Далее следуют `n` строк, в каждой записано целое число — температура соответствующего дня.

Ограничения:

`0 ≤ n ≤ 1000`

`-80 ≤ температура ≤ 80`

### Формат вывода

Если `n = 0`, вывести:

```text
Нет данных
```

Иначе вывести три строки:

```text
Жарких дней: <количество>
Максимальная серия: <длина>
Серия закончилась в день: <номер дня>
```

Если жарких дней не было, последнюю строку вывести так:

```text
Серия закончилась в день: 0
```

## 9. Таблица продаж

Магазин работает `n` дней и продаёт `m` категорий товаров. Для каждого дня вводится количество проданных единиц по каждой категории.

Нужно определить общую сумму проданных единиц, номер дня с наибольшими суммарными продажами и номер категории, которая была продана в наибольшем количестве за весь период.

Если лучший день встречается несколько раз, выбрать последний. Если лучшая категория встречается несколько раз, выбрать категорию с меньшим номером.

### Формат ввода

В первой строке записаны два целых числа `n` и `m` — количество дней и количество категорий.

Далее следуют `n` строк. В каждой строке записано `m` целых неотрицательных чисел — продажи категорий за соответствующий день.

Ограничения:

`1 ≤ n ≤ 100`

`1 ≤ m ≤ 100`

`0 ≤ продажи ≤ 100000`

### Формат вывода

Вывести три строки:

```text
Всего продано: <сумма>
Лучший день: <номер дня>
Лучшая категория: <номер категории>
```

## 10. Турнир: лидер после последнего тура

В турнире участвуют `n` игроков. Турнир состоит из `m` туров. За каждый тур каждый игрок получает целое количество очков, которое может быть положительным, нулевым или отрицательным.

Нужно определить итогового победителя по сумме очков.

Если несколько игроков набрали одинаковую максимальную сумму, победителем считается тот, кто набрал больше очков в последнем туре. Если равенство сохраняется, выбирается игрок с большим номером.

Также нужно определить, сколько игроков закончили турнир с отрицательной итоговой суммой.

### Формат ввода

В первой строке записаны два целых числа `n` и `m` — количество игроков и количество туров.

Далее следуют `m` строк. В каждой строке записано `n` целых чисел — результаты игроков в соответствующем туре.

Ограничения:

`1 ≤ n ≤ 100`

`1 ≤ m ≤ 100`

`-10000 ≤ результат за тур ≤ 10000`

### Формат вывода

Вывести три строки:

```text
Победитель: игрок <номер>
Итоговый результат: <сумма>
Игроков с отрицательным результатом: <количество>
```
