# Задача 1. Мониторинг состояния сервера

Компания разработала систему мониторинга API. Сервер обрабатывает запросы и возвращает HTTP-коды ответов:

- `200–299` — успешный запрос;
- `400–499` — ошибка клиента;
- `500–599` — ошибка сервера.

Для каждого запроса фиксируется время ответа в миллисекундах.

## Условие

Напишите программу, которая анализирует работу сервера.

Сначала пользователь вводит количество запросов `N`. Затем для каждого запроса вводит HTTP-код и время ответа в миллисекундах (каждое значение с новой строки). Сохраните данные в списке кортежей.

Программа должна:

1. Посчитать количество успешных запросов, ошибок клиента и ошибок сервера.
2. Найти самый медленный запрос и вывести его HTTP-код и время выполнения.
3. Рассчитать среднее время ответа только для успешных запросов. Если их нет, вывести `0`.
4. Посчитать запросы, время ответа которых превышает 500 мс.
5. Найти максимальное количество **подряд идущих** ответов с кодами `500–599`.
6. Определить состояние сервера:
   - `STABLE` — ошибок сервера нет;
   - `WARNING` — ошибки сервера есть, но максимальная серия не превышает двух;
   - `CRITICAL` — минимум три ошибки сервера идут подряд.

**Дополнительное задание:** вывести номера первого и последнего запросов с ошибкой сервера. Нумерация начинается с 1.

## Пример ввода

```text
6
200
120
500
800
503
920
200
700
404
100
502
610
```

## Пример вывода

```text
Успешных запросов: 2
Ошибок клиента: 1
Ошибок сервера: 3
Среднее время успешного запроса: 410.0
Медленных запросов: 4
Самый медленный запрос: 503, 920 мс
Максимальная серия ошибок сервера: 2
Статус сервера: WARNING
```

# Задача 2. Диспетчер задач операционной системы

Операционная система управляет очередью процессов, ожидающих выполнения. Обычные процессы добавляются в конец очереди, приоритетные — в начало. После выполнения процесс удаляется из очереди.

## Условие

Напишите программу управления очередью процессов с возможностью отмены последней успешной операции.

Сначала пользователь вводит количество команд `N`, затем — команды по одной. Для команд `1`, `2` и `4` следующей строкой вводится имя процесса.

| Команда | Действие |
|---|---|
| `1` | Добавить процесс в конец очереди |
| `2` | Добавить приоритетный процесс в начало |
| `3` | Выполнить первый процесс |
| `4` | Удалить ожидающий процесс по имени |
| `5` | Отменить последнее успешное изменение |

Изначально очередь и список выполненных процессов пусты.

Программа должна:

1. Обрабатывать команды в порядке поступления.
2. Не добавлять процесс, если такое имя уже есть в очереди; выводить `PROCESS EXISTS`.
3. При выполнении первого процесса переносить его из очереди в список выполненных процессов.
4. Если очередь пуста, при команде `3` выводить `QUEUE EMPTY`.
5. Если удаляемого процесса нет в очереди, выводить `PROCESS NOT FOUND`.
6. При команде `5` восстанавливать очередь и список выполненных процессов в состоянии **до последнего успешного изменения**. Повторная отмена без новой успешной операции невозможна; выводить `NOTHING TO UNDO`.
7. После обработки всех команд вывести очередь, список выполненных процессов и размеры обоих списков.

Неудачные операции не должны перезаписывать сохранённое состояние для отмены.

**Дополнительное задание:** реализовать команду `6` (`CLEAR`) — удалить все ожидающие процессы, не затрагивая выполненные, с возможностью отмены.

## Пример ввода

```text
6
1
API
1
DB
2
HOTFIX
3
4
DB
5
```

## Пример вывода

```text
Очередь процессов:
['API', 'DB']
Выполненные процессы:
['HOTFIX']
Ожидают выполнения: 2
Выполнено: 1
```

# Задача 3. Восстановление данных после передачи по сети

Большое сообщение передаётся по сети в виде пакетов. Пакеты могут поступать не по порядку, дублироваться или теряться. Иногда приходят пакеты с неправильными номерами.

## Условие

Напишите программу для восстановления исходного сообщения.

Пользователь вводит:

1. Число `N` — сколько пакетов должно быть в сообщении;
2. Число `M` — сколько пакетов фактически получено;
3. Для каждого из `M` пакетов — его номер и текстовое содержимое (на отдельных строках).

Правильные номера пакетов — целые числа от `1` до `N`. Полученные пакеты необходимо сохранить в списке кортежей.

Программа должна:

1. Игнорировать пакеты с номерами вне диапазона `1–N`, подсчитывая их количество.
2. Определять дубликаты — пакеты, чей корректный номер уже встречался. Оставлять только первый пакет с таким номером.
3. Подсчитывать количество дубликатов.
4. Находить номера отсутствующих пакетов.
5. Восстанавливать порядок пакетов по возрастанию номера.
6. Если все пакеты присутствуют, объединять их текст в одно сообщение **без разделителей**.
7. Если каких-либо пакетов не хватает, выводить `MESSAGE INCOMPLETE`.

**Ограничение:** использовать `sort()` и `sorted()` нельзя.

**Дополнительное задание:** если повторно пришёл пакет с уже встречавшимся номером, но другим содержимым, выводить `DATA CONFLICT`.

## Пример ввода

```text
5
6
3
C
1
A
5
E
3
C
7
X
2
B
```

## Пример вывода

```text
Уникальных корректных пакетов: 4
Дубликатов: 1
Пакетов с неверным номером: 1
Отсутствующие пакеты: 4
MESSAGE INCOMPLETE
```

# Задача 4. Обнаружение попыток взлома аккаунтов

Сервис авторизации хранит результаты попыток входа пользователей:

- `1` — правильный пароль;
- `0` — неправильный пароль.

После трёх неудачных попыток **подряд для одного пользователя** его аккаунт блокируется. Попытки разных пользователей могут чередоваться.

## Условие

Напишите программу, которая анализирует попытки авторизации и блокирует подозрительные аккаунты.

Пользователь вводит количество попыток `N`. Далее для каждой попытки отдельно вводит логин и результат авторизации (`0` или `1`).

Программа должна:

1. Сформировать список уникальных логинов.
2. Для каждого пользователя независимо считать последовательные неудачные попытки.
3. При успешном входе сбрасывать счётчик ошибок этого пользователя.
4. После третьей неудачной попытки подряд блокировать аккаунт.
5. После блокировки отклонять любые следующие попытки этого пользователя независимо от правильности пароля.
6. Посчитать количество успешных входов и попыток, отклонённых из-за **уже установленной** блокировки.
7. Вывести список заблокированных аккаунтов в порядке их блокировки и их количество.

Попытка, во время которой достигнут лимит из трёх ошибок, приводит к блокировке, но не считается попыткой, отклонённой из-за *уже установленной* блокировки.

**Дополнительное задание:** реализовать отдельную команду администратора для разблокировки аккаунта со сбросом счётчика ошибок.

## Пример ввода

```text
9
alice
0
bob
0
alice
0
bob
1
alice
0
alice
1
bob
0
bob
0
bob
0
```

## Пример вывода

```text
Заблокированные аккаунты:
alice
bob
Успешных входов: 1
Отклонено из-за блокировки: 1
Всего блокировок: 2
```

# Задача 5. Система контроля версий приложения

Приложение состоит из модулей, каждый из которых имеет собственную версию. Разработчики вносят изменения в рабочую конфигурацию, а пользователи работают с активной версией приложения.

Нужно создать упрощённую систему выпуска и отката релизов.

## Условие

Сначала пользователь вводит количество команд `N`, затем команды по одной.

| Команда | Действие |
|---|---|
| `1` | Изменить версию модуля или добавить модуль |
| `2` | Выпустить релиз (`DEPLOY`) |
| `3` | Откатиться к предыдущему релизу (`ROLLBACK`) |
| `4` | Показать активную конфигурацию |

Для команды `1` пользователь дополнительно вводит название модуля и номер его версии на отдельных строках. Номер версии хранится как строка.

В начале программы рабочая и активная конфигурации пусты, а история релизов не содержит записей.

Программа должна:

1. При команде `1` изменять только рабочую конфигурацию: обновлять версию существующего модуля или добавлять новый.
2. При команде `2` сохранять прежнюю активную конфигурацию в истории и делать рабочую конфигурацию активной.
3. При команде `3` восстанавливать из истории предыдущую активную конфигурацию. Рабочая конфигурация после отката должна совпадать с восстановленной активной.
4. Если история пуста, при попытке отката выводить `ROLLBACK IMPOSSIBLE`.
5. При команде `4` выводить названия и версии всех активных модулей в порядке их добавления.
6. Подсчитать общее число выпущенных релизов и успешных откатов. При выводе команды `4` показывать эти счётчики.
7. Хранить предыдущие релизы независимо: изменение рабочего состояния не должно менять уже сохранённые версии.

**Дополнительное задание:** перед выпуском релиза выводить, какие модули добавлены и у каких изменилась версия относительно текущей активной конфигурации.

## Пример ввода

```text
7
1
auth
1.0
1
payments
1.0
2
1
auth
2.0
2
3
4
```

## Пример вывода

```text
ACTIVE RELEASE

auth: 1.0
payments: 1.0
Выпущено релизов: 2
Выполнено откатов: 1
```

# Задача 6. Анализатор логов и обнаружение аномалий

Приложение собирает сообщения от нескольких сервисов. Каждое сообщение имеет один из уровней важности:

- `INFO` — обычное событие;
- `WARNING` — предупреждение;
- `ERROR` — ошибка;
- `CRITICAL` — критический сбой.

## Условие

Напишите программу для анализа журнала событий.

Сначала пользователь вводит число событий `N`. Затем для каждого события вводит название сервиса и уровень важности (на отдельных строках). Сохраните события в список кортежей в порядке поступления.

Программа должна:

1. Подсчитать общее количество событий и количество сообщений каждого уровня.
2. Сформировать список уникальных сервисов в порядке их первого появления.
3. Для каждого сервиса посчитать количество сообщений `ERROR` и `CRITICAL`.
4. Найти сервис с наибольшим числом таких сообщений. При равенстве вывести все соответствующие сервисы.
5. Найти максимальную длину непрерывной серии событий с уровнями `ERROR` или `CRITICAL` во **всём журнале**, независимо от сервиса.
6. Создать отдельный список событий уровня `CRITICAL`, сохранив их порядок.
7. Рассчитать процент событий `ERROR` и `CRITICAL` от общего числа событий.

**Дополнительное задание:** найти все непрерывные серии длиной не менее двух событий уровня `ERROR` или `CRITICAL`; вывести начальную и конечную позиции каждой серии. Нумерация событий начинается с 1.

## Пример ввода

```text
8
auth
INFO
database
ERROR
auth
WARNING
database
ERROR
database
CRITICAL
auth
INFO
database
ERROR
payments
INFO
```

## Пример вывода

```text
Всего событий: 8
INFO: 3
WARNING: 1
ERROR: 3
CRITICAL: 1
Самый проблемный сервис: database
Ошибок и критических событий: 4
Максимальная серия ошибок: 2
Доля ошибок и критических событий: 50.0%
```
